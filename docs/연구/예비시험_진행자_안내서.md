# 예비 시험 진행자 안내서 (2026-12-01 ~ 12-04)

- 목적: 발표(12/7)·논문(12/11) 전에 **처음 보는 사람**이 앱을 혼자 쓸 수 있는지, 위험 인지가 바뀌는지, 사용성이 어떤지를 작게 확인한다 (본 연구가 아닌 **예비 시험**)
- 측정: ① 사전·사후 그림 점검(앱 자동) ② 장면별 위험 인지율·시간(앱 자동) ③ SUS 10문항 + 자체 5문항(앱 자동, 마지막 점검 뒤) ④ 관찰 기록지(진행자) ⑤ 짧은 면담 3문항
- 모든 수치는 앱의 **결과 파일(JSON)** 로 모은다. 이름·연락처·기기 정보는 파일에 없다(무작위 번호만)
- 이 안내서·동의서·기록지는 초안이다. **학교 연구윤리(IRB) 심의 대상인지 지도교수께 먼저 확인**한다(사람 대상 설문·관찰이므로)

## 1. 참여자
| 항목 | 기준 |
|---|---|
| 인원 | 5~8명 (예비 시험 — 통계 검정이 아니라 문제 찾기용. 사용성 문제는 5명 안팎에서 대부분 드러난다는 주장이 있으나 이 연구의 근거로 쓰지 않음) |
| 대상 | 건설현장 경력 1년 미만 또는 없음, 만 19세 이상. 가능하면 한국어가 서툰 사람 1명 이상(그림만 모드 확인) |
| 제외 | 이 앱을 만들거나 미리 본 사람 |
| 보상 | 0원 원칙 — 없음(필요하면 지도교수와 상의) |

## 2. 준비물 (참여자 1명당)
- 안드로이드 휴대전화 1대(크롬, 화면 6인치 안팎), 충전, 이어폰(듣기 확인용)
- 앱 주소: `https://wldp2003-ctrl.github.io/first-shovel/` — 시작 전 **타이틀 → 환경 설정 → 기록 → "기록 처음부터 다시 하기"**(확인 → 3초 누르기)로 앞사람 기록·보기 방식·소개 본 기록을 지운다. 타이틀로 돌아오고 "시작하기"만 보이면 된 것(“이어하기”가 보이면 안 됨)
- 동의서 2부(참여자·연구자 보관), 관찰 기록지 1장, 필기구, 시계(스톱워치)
- 진행자는 1명. 가능하면 기록 보조 1명

## 3. 순서 (약 35~45분)
| 순서 | 시간 | 진행자가 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 1 동의 | 5분 | 동의서를 함께 읽고 서명. 언제든 그만둘 수 있음을 말함 | |
| 2 안내 | 1분 | 아래 "안내 문장"만 읽는다 | 앱 사용법을 설명하지 않는다 |
| 3 사용 | 20~30분 | 앱을 건넨다. 기록지에 시간·막힌 곳·도움 요청을 적는다 | 화면을 가리키거나 답을 알려 주지 않는다 |
| 4 막힘 | — | 2분 넘게 멈추면 "지금 무엇을 찾고 계세요?"만 묻는다. 3분 넘으면 도움(기록지에 "도움" 표시) | |
| 5 설문 | 2분 | 마지막 점검 뒤 앱이 설문을 띄운다. 참여자가 스스로 답한다 | 문항을 풀어 설명하지 않는다(듣기 단추는 써도 됨) |
| 6 결과 저장 | 2분 | 내 기록 → 결과 파일 저장 → 파일 이름 끝 무작위 번호를 기록지에 적는다 | 이름을 파일에 적지 않는다 |
| 7 면담 | 5분 | 면담 3문항 (아래) | |

### 안내 문장 (그대로 읽기)
> "건설현장 첫 출근 전에 위험을 미리 보는 앱입니다. 혼자서 써 보세요. 저는 옆에서 앱이 쓰기 쉬운지를 보는 것이지, 당신을 평가하는 것이 아닙니다. 생각나는 것을 말로 해 주시면 도움이 됩니다. 끝나면 짧은 설문이 나옵니다."

### 면담 3문항
1. 가장 헷갈렸던 곳은 어디였나요?
2. 현장에 가서 떠오를 것 같은 그림이 있나요? 무엇인가요?
3. 출근 전에 다시 쓴다면 언제, 얼마나 쓸 것 같나요?

## 4. 그림만 모드 참여자 (한국어가 서툰 사람)
- 타이틀 → 시작하기 → "보기 방식"에서 참여자가 직접 고르게 한다(진행자가 고르지 않음). 무엇을 골랐는지 기록
- 설문은 한국어 문장이다 — **듣기 단추**로 들을 수 있다. 그래도 어려우면 설문은 건너뛰고(“건너뛰고 확인서 받기”) 기록지에 "설문 못 함(언어)"으로 적는다. 통역으로 대신 답하게 하지 않는다(번역본이 검증되지 않았으므로)

## 5. 결과 모으기
- 결과 파일(JSON)을 한 폴더에 모은 뒤: `node tools/aggregate-results.mjs <폴더>` → 같은 폴더에 `요약.csv`(참여자별 한 줄)와 화면 출력(평균)
- 요약 항목: 사전/사후 점수, 위험 인지율, 장면별 시간, 설문(SUS 점수 0~100, 자체 5문항), 보기 방식, 사용 시간
- 관찰 기록지는 무작위 번호로 결과 파일과 짝을 맞춘다

## 6. 해석할 때 주의 (논문 "한계"에 쓸 것)
- 예비 시험 인원이 적어 통계적 일반화를 하지 않는다 — 평균·범위·개별 사례 중심으로 쓴다
- 사전·사후 그림 점검은 9문제: 재인 6문제(5문제가 교육 장면과 **같은 그림**) + 전이 3문제(v21, 교육에 없는 장소·물체). 재인 점수 상승에는 "같은 그림을 본 효과"가 섞이므로(라운드 2, `docs/점검/라운드_2.md`) 결과 파일의 `pre.core`·`post.core`(재인)와 `pre.xfer`·`post.xfer`(전이)를 따로 본다 — `aggregate-results.mjs` 가 열을 나눠 준다
- 이전 버전(6문제)으로 처음 점검을 한 참여자는 앱이 재인 6문제끼리만 비교해 보여 준다
- SUS 한국어 문장은 이 앱에서 옮긴 것으로, 검증된 한국어판인지 확인하지 못했다
- 참여자가 실제 신규 근로자가 아닐 수 있다(대리 참여자)
