# 03. 설계 원칙

> 원칙은 v9~v20의 설계 결정(CHANGELOG)과 1장의 문제(P1~P4), 2장의 공백에서 끌어냈다. 원칙마다 "왜(근거)", "어떻게(구현)", "무엇으로 확인했나(검증)"를 둔다. 확인 방법의 자동 점검 도구는 저장소 밖 `tools/`에 있다.

**표 3-1. 첫 삽 설계 원칙**

| 번호 | 원칙 | 근거 | 구현 | 확인 방법 |
|---|---|---|---|---|
| DP1 | **법정 교육을 대신하지 않는 보조 도구** — 출근 전 미리 보기·반복용 | 표 2-1, 법정 교육 이수 체계를 흐리지 않기 위함 | 타이틀 아래·확인서·정보 화면에 "법정 안전교육을 대신하지 않아요" 고지, 확인서에 "이수증이 아님" | 화면 문구(그림만 모드에서도 숨기지 않음, 그림만 규칙 1절) |
| DP2 | **먼저 알고 → 찾고 → 어떻게 → 정리** — 구역마다 같은 순서 | 처음 보는 사람이 무엇을 찾는지 모르면 무작위로 누름(P1) | 미리 보기(하는 일·조심할 위험 종류 아이콘) → 상황 문장 읽고 장면에서 찾기 → 찾은 위험 하나로 "어떻게 할까" → 결과·현장 안전 카드 | audit 자동 플레이 7구역 전부 같은 순서(그림 5-3~5-6) |

## 3.1 원칙 사이의 긴장과 선택
- **DP5(글 없이) vs DP6(근거).** 근거 칩은 글이다. 그림만 모드에서는 근거를 숨기고 글과 그림 모드에서만 보이게 했다. 근거 확인은 글을 읽는 사람(동료·관리자·검토자)의 일로 보았다.
- **DP5 vs 핵심 안전 문장.** 그림만 모드에서도 위험마다 1줄의 안전 문장은 남겼다. 안전 카드가 이미지로 저장되어 TBM에서 공유되기 때문이다. 이 선택은 사람 확인이 필요한 판단으로 기록했다(`docs/AI_사용기록.md`).
- **DP2(같은 순서) vs 게임성.** 계급·연속 출근·별은 학습 순서 밖의 동기 요소다. 별은 "힌트 없이 찾은 정도"로 학습과 묶었고, 계급·연속 출근은 장식에 가깝다는 지적(애매한 구현 12)을 한계로 둔다.
- **DP3 vs 측정.** 사전·사후 점검의 그림 쌍 6개 중 5개가 교육 장면과 같아, 측정이 "본 그림의 재인"에 가깝다(7.5절).
