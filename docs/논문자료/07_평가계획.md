# 07. 평가 계획

> 작성: 2026-11-25 (라운드 2). 이 문서는 예비 시험(2026-12-01~04)의 설계를 정리한 것이며, 결과는 시험 후 `11_예비시험_결과.md`(예정)에 쓴다.

## 7.1 평가 목적
본 연구의 평가는 다음 세 질문에 답하는 것을 목적으로 한다.

- **평가 질문 1(사용 가능성).** 건설현장 경험이 없거나 적은 사람이 안내 없이 앱의 본 과정(사전 점검 → 7구역 → 멈추고 알려요 → 사후 점검)을 끝까지 수행할 수 있는가.
- **평가 질문 2(위험 인지).** 앱 사용 전후에 그림 기반 위험 판별 점수와 구역별 위험 인지율은 어떠한가.
- **평가 질문 3(사용성).** 참여자가 인식한 사용성(SUS)과 그림 중심 설계에 대한 인식(자체 5문항)은 어떠한가.

## 7.2 평가 설계
단일 집단 사전·사후 설계의 **예비 시험**으로 수행한다. 참여자 수가 적으므로(5~8명) 추론 통계로 일반화하지 않고, 기술 통계(평균·최소·최대)와 개별 관찰을 중심으로 보고한다.

**표 7-1. 평가 도구와 수집 방법**

| 구분 | 도구 | 문항·내용 | 수집 | 비고 |
|---|---|---|---|---|
| 위험 판별 | 사전·사후 그림 점검 | 같은 9문제(그림 쌍 중 안전한 쪽 고르기), 순서 무작위 — **재인 6**(교육 그림 5 + 교육 밖 1) + **전이 3**(v21, 시험 전용) | 앱 자동 | 재인·전이 점수를 따로 기록(`core`·`xfer`). 5문제는 교육 장면과 같은 그림(7.5절) |
| 위험 인지 | 구역별 찾기 기록 | 구역 7곳, 위험 31개 — 찾은 수/전체, 시간, 별, 잘못 누른 수 | 앱 자동 | 힌트를 쓰면 별 감소 |
| 행동 순서 | 멈추고 알려요 | 3단계 순서 맞추기 — 시도 수, 틀린 수, 시간 | 앱 자동 | |
| 사용성 | SUS | 10문항, 5점 척도 (Brooke, 1996) | 앱 자동(사후 점검 뒤) | 0~100점으로 환산 |
| 설계 인식 | 자체 5문항 | 그림 이해, 글 없이 진행, 행동 순서 기억, 현장 회상, 다시 쓸 의향 | 앱 자동 | 연구자가 만든 문항, 타당화 안 됨 |
| 관찰 | 관찰 기록지 | 막힌 곳(2분)·도움(3분), 시간, 혼잣말 | 진행자 | `docs/연구/관찰_기록지.md` |
| 면담 | 3문항 | 헷갈린 곳, 떠오를 그림, 다시 쓸 때 | 진행자 | |

## 7.3 설문 문항
앱은 사후 점검의 결과 화면에서 "기초 확인서 받기"를 누르면 설문 첫 장을 보여 준다. 참여자는 설문을 시작하거나 건너뛸 수 있으며, 건너뛰어도 확인서를 받는다. 각 문항은 한 화면에 하나씩 나오고, 답은 얼굴 그림이 있는 5개 단추(1 전혀 아니다 ~ 5 매우 그렇다)로 고른다. 문항마다 듣기 단추가 있다.

**표 7-2. SUS 10문항(앱 화면 문장)**

| 번호 | 문장 | 방향 |
|---|---|---|
| 1 | 이 앱을 자주 쓰고 싶다. | 긍정 |
| 2 | 이 앱은 쓸데없이 복잡하다. | 부정 |
| 3 | 이 앱은 쓰기 쉬웠다. | 긍정 |
| 4 | 이 앱을 쓰려면 잘 아는 사람의 도움이 필요할 것 같다. | 부정 |
| 5 | 이 앱의 여러 기능이 잘 어우러져 있다. | 긍정 |
| 6 | 이 앱은 앞뒤가 맞지 않는 부분이 너무 많다. | 부정 |
| 7 | 대부분의 사람이 이 앱을 금방 익힐 것 같다. | 긍정 |
| 8 | 이 앱은 쓰기가 매우 번거롭다. | 부정 |
| 9 | 이 앱을 쓰면서 자신 있었다. | 긍정 |
| 10 | 이 앱을 쓰기 전에 배워야 할 것이 많았다. | 부정 |

SUS 점수는 홀수 문항은 (답 − 1), 짝수 문항은 (5 − 답)으로 바꾸어 더한 뒤 2.5를 곱해 0~100점으로 계산한다(Brooke, 1996). 앱의 `susScore()`와 `tools/aggregate-results.mjs`가 같은 식을 쓴다.

> **번역 확인 필요.** 위 한국어 문장은 본 연구에서 원문(Brooke, 1996)을 옮긴 것이다. 검증된 한국어판 SUS의 출처를 확인하지 못했으므로(2026-11-25 검색), 논문에는 "연구자 번역"으로 밝히고 한계에 적는다. 검증된 한국어판을 찾으면 그 문장으로 바꾸고 출처를 적는다.

**표 7-3. 자체 5문항(설계 인식)**

| 번호 | 문장 | 관련 설계 원칙 |
|---|---|---|
| 자체 1 | 그림을 보고 무엇이 위험한지 알 수 있었다. | 그림 우선 |
| 자체 2 | 글을 읽지 않아도 다음에 무엇을 누를지 알 수 있었다. | 글 없이 진행 |
| 자체 3 | 위험하면 멈추고, 피하고, 알리는 순서를 기억한다. | 행동 연결 |
| 자체 4 | 현장에서 오늘 본 위험이 떠오를 것 같다. | 현장 전이 |
| 자체 5 | 출근 전에 구역 하나씩 다시 해 볼 생각이 있다. | 짧은 반복 |

## 7.4 자료 수집과 처리
1. 진행자는 시험 전 앱의 기록을 지운다(환경 설정 → 기록 처음부터 다시 하기). 이때 보기 방식과 소개를 본 기록도 함께 지워져 참여자마다 같은 첫 화면에서 시작한다.
2. 참여자가 끝나면 "내 기록 → 결과 파일 저장"으로 JSON 파일을 받는다. 파일에는 무작위 번호, 점수, 시간, 사용 시간대(시), 설문 답만 있고 이름·연락처·기기 정보는 없다.
3. 모든 파일을 한 폴더에 모아 `node tools/aggregate-results.mjs <폴더>`로 참여자별 요약(`요약.csv`)과 평균·범위를 만든다.
4. 관찰 기록지는 결과 파일의 무작위 번호로 짝을 맞춘다. 동의서는 따로 보관하며 이름과 번호를 잇는 표를 만들지 않는다.

## 7.5 타당도 위협과 대응

**표 7-4. 알려진 한계**

| 위협 | 내용 | 대응 |
|---|---|---|
| 같은 그림 효과 | 재인 6문제 중 5문제(1-1, 2-2, 0-2, 3-1, 5-1)가 교육 장면의 그림 쌍과 같다. 사후 점수 상승에 "본 그림을 다시 알아본 효과"가 섞인다 | v21: **전이 3문제**를 더했다 — 같은 위험 종류를 교육 7구역에 없는 장소·물체로 그린 시험 전용 그림 쌍(x-1 다른 층의 작은 바닥 구멍 ← 1-1, x-2 철골 보 위 안전대 ← 2-2, x-3 매단 파이프 묶음 아래 통행 ← 3-1, 근거는 바탕 문제와 같은 출처). 재인 점수와 전이 점수를 따로 보고하고, 전이 점수 변화만 "새 상황에 적용"의 근거로 쓴다. 전이 문항도 3개뿐이고 바탕 문제와 구도가 비슷해 근전이(near transfer)로 한정한다 |
| 작은 표본 | 5~8명 | 기술 통계만 보고, 일반화하지 않는다 |
| 대리 참여자 | 실제 신규 근로자가 아닐 수 있다 | 참여자 특성(경력·한국어)을 기록하고 결과와 함께 보고한다 |
| 번역 | SUS 한국어 문장이 검증본이 아니다 | 7.3절 표기 |
| 천장 효과 | 사전 점검에서 이미 6/6일 수 있다 | 구역별 인지율·시간·힌트 사용을 함께 본다 |
| 진행자 영향 | 진행자가 앱을 만든 사람이다 | 안내 문장을 정해 읽고, 도움 기준(3분)을 정해 기록한다 |
| 전문가 확인 | 교육 문장의 전문가 확인이 아직 0개다 | 위험 장면 31개와 전이 문항 3개(v21, "바탕 문제와 같은 위험 종류인가" 기준 추가) 검토지(`docs/전문가검토지_장면.html`)로 CVI를 받는다. 받기 전 결과는 "원문 대조까지 확인"으로 표기한다 |
