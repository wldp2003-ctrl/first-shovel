# 에셋 라이선스 (v17)

앱에 들어가는 3D 모델, 텍스처, 렌더링 이미지의 출처와 이용 조건을 적습니다. 그림과 사진 전체 목록은 `data/media.json`에 있고, `node tools/smoke-v13.mjs`의 7번 항목이 빠진 기록이 없는지 확인합니다.

## 결정: 외부 3D 에셋 없이 코드로 직접 모델링 (②안)
- 프롬프트의 우선순위는 ① 무료 CC0 에셋(Kenney, Quaternius, Poly Pizza 등) → ② Blender 직접 모델링 → ③ 혼합이었습니다.
- v17 1단계에서는 **② 직접 모델링(three.js 코드)**을 골랐습니다. 이유는 네 가지입니다.
  1. 위험 장면의 핵심은 **위험한 모습과 안전한 모습의 차이 하나**(턱끈, 안전대 줄, 난간 한 칸, 덮개)입니다. 이 차이를 우리가 직접 바꿀 수 있어야 하는데, 기성 에셋은 보호구 디테일을 고치기 어렵습니다.
  2. 지도와 위험 장면이 **같은 소품 함수**(`js/learn/props3d.js`)를 함께 씁니다. 그래서 그림 스타일이 하나로 맞습니다.
  3. 내려받을 모델 파일이 없어서 용량이 작고(3D 전체 약 4MB), 오프라인 캐시가 단순합니다. 라이선스를 관리할 파일도 0개입니다.
  4. 색은 `css/tokens.css` 토큰만 씁니다. 그래서 v12.1 테마와 안전 4색 의미가 자동으로 유지됩니다.
- CC0 에셋을 나중에 섞을 때는 아래 "추가 규칙"을 따릅니다.

## 추가 규칙 (CC0·CC-BY 에셋을 넣을 때)
1. CC0 또는 CC-BY만 씁니다. 그 밖의 라이선스(CC-BY-NC, 출처 불명, 상품 이미지)는 쓰지 않습니다.
2. 이 표에 `파일 | 출처 URL | 작가 | 라이선스 | 받은 날 | 고친 점`을 한 줄씩 적습니다.
3. CC-BY 에셋은 앱 안의 크레딧 화면(설정 아래 "만든 사람들")에 작가와 라이선스를 표기합니다. 이 화면은 첫 CC-BY 에셋이 들어올 때 함께 만듭니다.
4. 형식은 glTF/GLB, Draco 또는 meshopt 압축입니다. 같은 모델은 인스턴싱합니다. 색은 토큰 팔레트로 다시 칠해서 스타일을 맞춥니다.
